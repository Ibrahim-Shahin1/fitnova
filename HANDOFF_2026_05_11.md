## Why the failure happened (root cause)

The QEVD `feedbacks_short_clips.json` text feedbacks were parsed by my custom **lexicon classifier** (`backend/training/preprocessing/qevd_label_builder.py`) to derive numeric quality scalars. That classifier:
- Picks up class-correlated keywords ("squats" feedbacks mention "knees" a lot, "pushups" feedbacks mention "elbows")
- Doesn't separate "good knees" from "bad knees" within the same exercise
- Results: quality labels are mostly determined by exercise CLASS, not actual form

Joint-error head learned class-level priors. Quality head converged to ~0.71 (the mean) for all squats. Action head learned to predict "other" 99% of the time (would have been even worse if the class map name was wrong — see Bug #1 below).

This was **Risk #1 in the master plan** (`C:\Users\tsh_x\.claude\plans\i-am-now-on-zazzy-brooks.md` Part II §II.11). Mitigation specified: GPT-4o-mini batch relabel ($2-5 API cost, ~30 min).

## What we built in the recovery (THIS CHAT)

### 1. Geometric form validator (DONE, tested, wired)

Pure-NumPy rule engine that runs ALONGSIDE the ML model. Drives the user-facing rep count, quality label, and red-flag chips because the ML's heads are degenerate.

**Files:**
- `backend/services/form_geometry.py` — `GeometricFormValidator` class + `RepStateMachine` + rule evaluators
- `backend/config/exercise_rules/__init__.py` — registry
- `backend/config/exercise_rules/squat.py` — ONLY squat rules so far
- `backend/services/test_form_geometry.py` — **39 tests, all pass**

**Rep state machine** (per user spec, trigger policy A = completion):
```
STANDING → DESCENDING → ASCENDING → STANDING  = +1 REP
```
- Calibrates standing baseline from first 20 frames (smallest hip_y observed)
- Rejects bobbing (< 7% frame-height descent)
- Rejects half-reps (< 8% total displacement)
- Never double-counts (1 cycle = 1 rep, not 2)

**Squat form rules (3):**
1. `back_excessive_lean` — trunk angle from vertical. Safe < 60°, red flag > 85°.
2. `knees_caving` — knee_dist / ankle_dist ratio. Safe > 0.55, red flag < 0.25. **Loosened after user feedback that previous thresholds (0.75/0.55) were too sensitive.**
3. `insufficient_depth` — pelvis-y vs knee-y at bottom of rep. Only fires when `at_bottom == True`.

**Severity labels per rule** (no percentages in UI):
- Caving: "Small Knee Caving" / "Notable Knee Caving" / "Dangerous Knee Caving"
- Lean: "Slight Forward Lean" / "Notable Forward Lean" / "Dangerous Forward Lean"
- Depth: "Shallow Squat" / "Quarter Squat" / "Too Shallow — Bend Knees More"

**Quality label** (replaces percentage bar):
- 0.85+: Excellent Form / 0.70+: Good Form / 0.50+: Fair Form / 0.30+: Needs Work / else Bad Form

**Joint-error filtering**: `relevant_joint_groups: [knees, hips, trunk]` for squat — shoulders/elbows/neck are zeroed out before sending to Flutter. Fixes user complaint that v6's ML head fires shoulder warnings on squats.

### 2. Backend wiring (DONE)

- `backend/services/form_session.py`: instantiates `GeometricFormValidator(selected_exercise)` per session, calls `update(landmarks)` every valid frame, **blends** geometric + ML output:
  - `rep_count`: geometric is authoritative (ML boundary head dead)
  - `quality_score`: `0.7 * geometric + 0.3 * ML`
  - `joint_errors`: per-group max of both, then zeroed for non-relevant joints
  - `active_flags`: `[{name, label, severity}, ...]` ← new payload field
  - `quality_label`: e.g. "Good Form" ← new payload field
  - `phase`: STANDING/DESCENDING/ASCENDING ← new payload field
  - `geometric_ready`: bool, true after calibration ← new payload field

- `backend/services/form_analyzer.py`: v6 detection priority (v6 → v5.2 → v4). Loads `v6_supervised.weights.h5` + `model_config.json` + `qevd_exercise_map.json`. `_predict_window_v6()` method handles inference with debug logging when `FITNOVA_DEBUG=1`.

- `backend/services/exercise_sanity.py`: Fixed to find `qevd_exercise_map.json` (v6) OR `exercise_labels.json` (v5.2). No more "detector disabled" warnings.

- `backend/app.py`: `/health` endpoint now returns model_version + model_ready + n_exercises so you can verify v6 is loaded.

## Known issues / gotchas

1. **Camera lag on BlueStacks** — partly host-webcam pipeline latency, can't fully fix from Flutter. Mitigated by `ResolutionPreset.medium` + 100ms interval. If user still complains, next option is `startImageStream` + on-device YUV→JPEG conversion (3-4 hours of work).

2. **MediaPipe warnings at startup** — `inference_feedback_manager.cc:121 ... Feedback manager requires a model with a single signature inference` ×2 — these are MediaPipe internal noise, harmless.

3. **TF GPU on Windows** — TF >=2.11 doesn't support native Windows GPU. Always uses CPU. For 1M-param model this is fine (~5-15ms per window).

4. **ExerciseMismatchDetector** under v6 — silently inactive because FitNova UI names ("squat") don't match QEVD class names ("squats"). Not a bug in v6 mode; it just doesn't fire. Would need a v6→FitNova reverse mapping if we want it back.

5. **Bug from D9 fix** — `reality_check_v6.py` defaults `--exercise squat` (singular). v6's QEVD class is `squats` (plural). User must pass `--exercise squats` or top-1 falls back to `__other__` idx 24. Already documented in the D9 reality-check report.

6. **`/content` is ephemeral on Colab** — if Colab disconnects mid-D6, the .npz cache is gone. Recovery: rerun the Drive-API cache step (~15-25 min).

7. **`drive.flush_and_unmount()` can hang for 30-60+ minutes** silently. I now use Drive-API verification instead in the D6 notebook's Cell 7. Don't add flush back.
