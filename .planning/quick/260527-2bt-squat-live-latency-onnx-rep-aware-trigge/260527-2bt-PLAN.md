# Quick Task 260527-2bt: Squat live latency + rep-aware trigger + upload replay

## Why

User feedback after the D-05 UI shim: live feedback is too laggy, and the upload result is a
static screen (they want a video replay showing the model's per-rep analysis). Measured the live
pipeline:

- Serving machine is **CPU-only** (no GPU; torch 2.12.0+cpu).
- Full-quality R(2+1)D-18 forward floor: single-seed ~0.75s, 3-seed ensemble ~1.9s (sequential),
  ~1.9s (parallel — CPU is compute-saturated, parallelism barely helps).
- **ONNX Runtime: numerically identical (max abs diff 2.4e-7) and ~1.6× faster** — single 0.47s,
  ensemble 1.42s. Zero quality tradeoff (same fp32 math).
- Real culprit isn't just inference: the live trigger fires on a **45-frame clock** (~7s) and
  classifies the rolling window at that tick — so when the user pauses after a rep it analyzes the
  **standing pose, not the rep** (lag + wrong-window correctness bug).

## Decisions (locked)

- **D1 — ONNX everywhere, no quality tradeoff.** Route inference through ONNX Runtime (parity
  2.4e-7). Keep a PyTorch fallback if onnxruntime/export is unavailable.
- **D2 — Full ensemble is the default (no compromise).** Live + upload both default to the 3-seed
  ensemble via ONNX (~1.4s). `SQUAT_INFERENCE_SEEDS` knob still lets the user drop to single-seed
  (0.47s, −0.018 macro, invisible in the live domain) without a rebuild.
- **D3 — Live trigger is rep-aware (motion-gated), not clock-based.** Detect rep-end via motion
  energy → classify that rep's frames immediately. User chose auto-detect over a manual button.
- **D4 — Upload becomes a replay**, not a static screen: play the video back with per-rep KIE/KFE
  verdicts synced to playback + the model's lower-body crop box overlaid ("eyes of the model").
  Backend must return each rep's time interval (not just detected-error intervals).

## Tasks

### Task 1 — ONNX inference in SquatFormService (the latency win)
- **files:** `backend/services/squat_form_service.py`, `backend/tests/test_squat_form_api.py`,
  `backend/requirements.txt`
- **action:** At load, after each torch model, export+cache `seedN/best.onnx` and open an
  onnxruntime `InferenceSession` (intra-op threads tuned; startup warmup). `classify_clip` forwards
  through ONNX when sessions exist, else the torch fallback. Preprocessing (`kneeaware_spatial_val`)
  + `aggregate_sigmoid_mean` + thresholds UNCHANGED. Add `onnxruntime`/`onnxscript` to requirements.
- **verify:** parity test (ONNX vs torch < 1e-4); `python -m pytest backend/tests/test_squat_form_api.py
  backend/tests/test_app.py -q` → all green; latency probe shows ~0.47s single / ~1.4s ensemble.
- **commit:** `feat(260527-2bt): ONNX Runtime inference in SquatFormService (1.6x, parity 2.4e-7)`

### Task 2 — Rep-aware auto live trigger
- **files:** `backend/services/rep_segmenter.py` (live motion-gated rep-end detector),
  `backend/app.py` (SquatLiveSession uses it), `backend/tests/test_squat_form_api.py`,
  `lib/screens/form_check_screen.dart` (+ provider: "analyzing" state)
- **action:** Add a live motion-energy rep-end detector (rising-then-settling edge) → on rep-end,
  classify the rep's buffered frames. Replace the fixed `LiveWindowTrigger` clock. Emit an
  `analyzing` signal so the UI shows a spinner while the ~1.4s forward runs. Default to ensemble.
- **verify:** WS tests green (updated for the new trigger); manual reasoning on motion edge cases.
- **commit:** `feat(260527-2bt): motion-gated rep-end live trigger + analyzing state`

### Task 3 — Upload replay (video + synced model analysis)
- **files:** `backend/app.py` (per-rep interval in UploadResponse), Flutter: new replay screen
  + `form_models.dart` (rep interval) + `video_upload_screen.dart` (navigate to replay) +
  route in `main.dart`
- **action:** UploadResponse carries each rep's `[start,end]` seconds. New D-05 replay screen:
  `video_player` playback + scrubber rep markers + per-rep KIE/KFE verdict synced to current time +
  the kneeaware lower-body crop box drawn over the video.
- **verify:** `flutter analyze` clean; backend tests green.
- **commit:** `feat(260527-2bt): upload video replay with synced per-rep model analysis`
