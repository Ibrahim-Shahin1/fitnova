# Quick Task 260526-wi7: Flutter form D-05 UI shim + exercise trim

## Why

Phase 5 replaced the form backend with a PyTorch Squat detector emitting the **D-05 schema**
(`rep_result`/`session_summary` over WS; `UploadResponse{exercise,total_reps,reps[{exercise,errors[{type,detected,confidence,severity_word,intervals}]}]}` over REST).
The Flutter form screens still consume the **old MediaPipe schema** (`frame_result`/`landmarks`/
`quality_score`/`FormSessionSummary`), so the live camera shows nothing and upload lands on a blank
50% screen. This shim rewires the form UI to D-05 so the Squat slice is demoable on BlueStacks.

Formally the polished Flutter form UI is v2-deferred (REQUIREMENTS UI-01/UI-02); this is a deliberate
**minimal demo shim**, not the polished UI. Tracked as demo-prep under `05-HUMAN-UAT.md` #2.

## Decisions (locked)

- **D1 — Keep old models as dead-but-compiling code.** `form_replay_screen.dart` + `main.dart`'s
  `/form-replay` route depend on `FormSessionSummary`/`timeline`/`SkeletonPainter`; deleting the old
  models would cascade-break compilation. Add D-05 models alongside; `form_replay` becomes unreachable
  (upload navigates straight to `/form-results`). Dead-code cleanup deferred.
- **D2 — Live `rep_result` is a time-window cadence, not rep detection.** `LiveWindowTrigger` fires on
  a clock (≥32 frames buffered AND ≥45 frames since last → ~every 4.5s @ ~10fps), NOT on detected reps.
  Label live as periodic **"form checks"**, not a rep counter (honesty — [[feedback_ai_correctness]]).
- **D3 — Drop pose-dependent UI.** New backend produces no landmarks/quality/mismatch. Remove the
  skeleton overlay, quality label, active-flag chips, phase pill, and mismatch banner from the live
  screen. Replace with: a "form checks: N" count + the latest check's KIE/KFE chips.
- **D4 — Exercise trim is client-side, NOT a backend JSON edit.** `exercises.json` is a shared
  27-exercise SSOT; `backend/tests/test_exercises_consistency.py` hard-asserts `len==27` + contiguous
  idx + label-drift-free vs `exercise_labels.json`. Trimming the JSON would break that test for zero
  benefit. The recommender/plan feature does NOT read `exercises.json` (verified). So: filter the
  picker client-side to the three Fitness-AQA exercises; backend untouched.
- **D5 — The three = Squat (`squat`, enabled), Overhead Press (`dumbbell_overhead_shoulder_press`,
  relabel "Overhead Press", coming-soon), Barbell Row (`barbell_row`, coming-soon).** Only Squat is
  implemented (OHP=Phase 6, Row=Phase 7); the other two are disabled "Coming soon" tiles so they never
  hit the backend 400 / wrong-model path.
